# Canonical extension types: coverage

Arrow defines a set of [canonical extension types](https://arrow.apache.org/docs/format/CanonicalExtensions.html):
named extensions in the reserved `arrow.` namespace, each over a fixed storage type, carried through IPC and the
C data interface as the field metadata keys `ARROW:extension:name` and `ARROW:extension:metadata`. An
implementation is not required to support any of them; one that does not recognize a name must keep the
storage type usable and pass the metadata along.

This page records what `zarrow` does with them. Evidence follows the rule in [`CLAUDE.md`](../CLAUDE.md):
every `yes` / `partial` row cites a source reference and a test reference, checked by
`tools/check_doc_evidence.py`.

Legend: **yes** = the behaviour exists and a test exercises it; **partial** = the type passes through the
generic extension mechanism but zarrow does not recognize the name, validate its metadata or check its storage
type; **no** = nothing.

`src/extension/canonical.zig` (exported as `zarrow.canonical_extensions`) recognizes every canonical name.
IPC and C data import call `validateType` on every extension field (also an extension that is the value type
of a dictionary): a canonical name over the wrong storage type or with malformed metadata is
`InvalidMetadata`; any other name passes through untouched, as the specification requires. `validateFull` of
an extension array calls `validateValues` for the value constraints. Metadata JSON goes through a strict,
non-recursive RFC 8259 validator (at most 64 KiB and nesting depth 8) before it is read.

## Canonical types

Every canonical type is recognized on IPC and C data import (`validateType`, `src/extension/canonical.zig:326`; IPC
`src/ipc/stream_reader.zig:1204`, C data `src/ffi/c_data.zig:481`), keeps its name and metadata through IPC
and the C data interface, and is usable as its storage type. The pyarrow 26 fixture
`src/extension/testdata/pyarrow_canonical.arrows` (written by `tools/interop/pyarrow_canonical_extensions.py`)
holds one column of each; zarrow reads it, validates it, writes it again (`interop-fixture-writer`
`canonical-ext`) and pyarrow reads that back with its registered types (`pyarrow_canonical_extensions.py
check`, run in CI).
